## 0. Lesehilfe

| Begriff | Bedeutung in diesem Dokument |
|---|---|
| **Owner** | führende Task aus R0-12 §1.1 (erste genannte R1- bzw. R3-Task) und die verantwortliche Komponente im Code (`Namespace\Klasse`) |
| **Trigger** | was den Ablauf auslöst (Akteur und Weg: UI, REST, Cron, Quelle) |
| **Vorbedingung** | Zustand, der vor dem Trigger gelten muss; Rechte nach R0-07 |
| **Events** | interne Outbox-Ereignisse (`ccap_outbox_event`, Free nur intern, **E-38/E-182**); Namen nach R0-09 §2.5 und R0-19 §5 |
| **UI** | Oberfläche, in der der Ablauf beginnt oder sein Ergebnis zeigt |
| **Retry** | Wiederholungs- und Idempotenzmechanik (Request-Key, Quellschlüssel, Outbox-Backoff, Lease) |
| **Audit** | Spur: `ccap_audit_log`-Aktion(en), `ccap_grant_event` (Grant-Historie, R0-09 §2.4) bzw. „keine“ mit Grund |
| **Release** | nach R0-04/R0-12: R1, R1+R3 (Kern R1, Adapter R3), R2, R3, R4 |
| **Spez.** | Abschnitt, der Zustände, Rechte und Fehler verbindlich regelt |
| **Test** | führender automatisierter Test als `Datei::Methode` (Datei ohne `.php`, Ordner `tests/integration`, sonst angegeben); Katalog-IDs ohne zuordenbaren Test stehen in §4 |
| `n/a (…)` | Dimension nicht anwendbar, Grund in Klammern |
| `R3` / `R2` / `R4` | Dimension gehört zu einem späteren Release; Verweis auf den dortigen Katalog |
| **Lücke** | anwendbar und R1, aber ohne automatisierten Test; Katalog-ID in Klammern |
