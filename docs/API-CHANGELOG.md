# API-Changelog (Vertrag v1)

Jeder Eintrag nennt: Version · Art (added/deprecated/removed/security) · Element · Ersatz · Fristende. Ein Eintrag ist Pflicht für jede Änderung an `docs/api/routes.v1.json` oder `docs/api/hooks.v1.json` (R0-19 §1.5).

## 0.1.0 (Vorabversion, noch kein stabiler Vertrag)

- **added** · REST-Namespace `course-captain/v1` mit den Routen aus `docs/api/routes.v1.json` (Lernen, Prüfung R-18…R-24, Autorenoberfläche, Zertifikate)
- **added** · einheitliches Fehlerformat (R0-19 §3.1), `X-Request-Id`, No-Store-Header auf allen Statuscodes
- **added** · Hooks aus `docs/api/hooks.v1.json`; stabil ist nur `course_captain_loaded_v1`
- **added** · Blöcke `course-captain/course-catalog`, `learning-link` und `certificate-verify` (`version` 1.0.0)
- **deprecated** · Shortcode `[course_captain_protected]` · Ersatz `[ccap_protected]` · Fristende: zwei Minor-Releases nach 1.0.0, mindestens 6 Monate
- **changed (vor Release)** · `ccap_answer_rate_limited` → `ccap_rate_limited` mit `details.bucket = answer`
- **changed (vor Release)** · `ccap_exam_finished` → `ccap_exam_already_submitted` bzw. `ccap_exam_aborted`
- **added** · Filter `course_captain_seo_indexable( bool $indexable, int $course )` (experimentell; kann Indexierbarkeit nur einschränken, R0-33 §1.3)
- **added** · `X-Robots-Tag: noindex, nofollow` auf allen Antworten von `course-captain/v1` (R0-33 LK-23)
- **added** · Action `course_captain_migration_fault` (intern, nur mit `COURSE_CAPTAIN_TESTING`; Fehlerinjektion für Migrationstests, R1-40) und WP-CLI `wp course-captain migrate [--status] [--format=json]`
- **added** · Filter `course_captain_hardening_conflicts( array $conflicts )` und `course_captain_hardening_limits( array $limits )` (experimentell, R0-31 §3.4); WP-CLI `wp course-captain hardening status|disable|unlock [--format=json]`; Header `Permissions-Policy` auf eigenen REST-Antworten bei aktivem `site_headers`
- **added** · WP-CLI `wp course-captain status [--format=json]` (Exit 1 bei `fail`), `cache flush [--user=<id>] [--course=<id>]`, `outbox status|retry|discard [--reason=<text>] [--yes]` (interne Abonnenten), `integrations status [--detected] [--format=json]` (nur Partnererkennung), `diagnostics [--output=<datei>]` (R1-38); keine neuen Hooks oder REST-Routen
- **changed (vor Release)** · Filter `course_captain_notification_hold`: Startwert ist jetzt der erkannte Haltemodus (`SiteIdentity::is_held()`, Site-Identität/Restore-Epoche, R1-23) statt `false`; kein neuer Hook. **added** · WP-CLI `wp course-captain identity [status|confirm <same_place|moved|copy>] [--format=json]`
- **added** · Text-/Dateiaufgaben (R1-46, R0-19 R-46, R-54…R-58): `GET /grading/queue` (Header `X-WP-Total`/`X-WP-TotalPages`), `GET /courses/{course}/assignments/{lesson}`, `PUT /courses/{course}/assignments/{lesson}/draft` (`If-Match` optional), `POST /assignment-submissions/{uid}/files` (multipart `file`, `Idempotency-Key` optional, 201/200 bei Wiederholung), `POST /assignment-submissions/{uid}/submit` (Wiederholung 200), `PUT /assignment-submissions/{uid}/grade` (`action: grade|return`, `points_milli`, `feedback`, `reason`; `Idempotency-Key` Pflicht); zusätzlich zum R0-19-Entwurf `GET /assignment-submissions/{uid}` (Eigentümer oder Bewertende) und `DELETE /assignment-submissions/{uid}/files/{media}` (Datei aus dem eigenen Entwurf entfernen). Neue Fehlercodes `ccap_submission_not_editable` (409), `ccap_submission_incomplete` (422), `ccap_submission_file_rejected` (422, `reason: dangerous|type|mime|size|empty|count|scan|upload|no_files`), `ccap_grade_invalid` (422, `reason: points|comment_required|reason_required`)
- **added** · Filter `course_captain_assignment_file_scan( bool|string|WP_Error $clean, string $path, array $meta )` (experimentell; nur `true` lässt eine Abgabedatei in die geschützte Ablage, R0-10 §4.5, E-289)
- **added** · REST `GET /imports/{id}` (Fortschritt), `POST /imports/{id}/step` (Browser-Schritt mit Zeitbudget), `POST /imports/{id}/cancel`, `POST /imports/{id}/resume`, `GET /imports/{id}/report?format=json|csv` (Befundreport, JSON mit Keyset-Seiten `after`/`per_page`, CSV mit BOM; Filter `severity`, `class`, `rule`, `phase`, `entity`) und WP-CLI `wp course-captain import status|run|cancel|report <id> [--format=csv|json] [--output=<datei>]` (R1-41); Hintergrundschritte über den bestehenden Hook `ccap_task_continue` mit `[import:<id>, cursor]`; keine neuen Hooks
- **added** · Admin-Einstellungen und Setup-Assistent (R1-32, nur admin-post, keine REST-Routen): Filter `course_captain_settings_rules( array $errors, string $tab, array $candidate, array $before )` (weitere Feldregeln), `course_captain_settings_risks( array $risks, string $tab, array $before, array $after )` (weitere Bestätigungen), `course_captain_risk_text( array $text, string $code, array $before, array $after )` (Dialogtexte), `course_captain_external_access_sources( bool $registered )` (blendet `enrollment.source_disabled_policy` ein), `course_captain_settings_roles_tab|_html|_save` (Andockpunkte des Rollen-Tabs, R1-34); alle experimentell
- **added** · Filter `course_captain_account_deletion_protected( bool $protected, WP_User $user )` (R1-34; schützt Konten vor der automatischen Löschung nach bestätigtem Löschantrag, Standard: Konten mit Verwaltungsrechten oder `ccap_*`-Rechten); Action-Handler für den vorhandenen Cron-Hook `ccap_privacy_export_generate`; keine REST-Routen
- **added** · Query-Parameter `_locale=user` auf allen Routen von `course-captain/v1`: `message`/`detail`/`title` im Fehlerformat kommen in der Profilsprache angemeldeter Personen, `code` bleibt unverändert (R0-25 §3.1, LOC-015, R1-19). Lernbereich-Formulare (Prüfungsraum `/<lernbereich>/pruefung/<id>`, Prüfungsstart im Kursraum) laufen serverseitig ohne JS über die bestehenden Dienste; keine neuen REST-Routen oder Hooks
- **added** · REST `GET /courses/{course}/practice?question=<id>[&module=<id>]` (gezieltes Üben einer Frage im Web-Pfad, R0-05 GM-074): Antwort wie `next-question` (Frage ohne Lösung, signiertes Token, Fortschritts-Payload, `reason = targeted`); fehlende/inkonsistente Parameter 422 `ccap_invalid_param`, Frage nicht im Kurs 404 `ccap_not_found`, Teilumfang/Drip 403 `ccap_content_locked` (`trial`/`drip`). REST `GET /reports/courses/{course}` (Fortschrittsbericht je Kurs, R0-07 RG-15, R0-05 GM-079): `learners[]` mit `user_id`, `display_name`, `stages` (Stufenzählung wie `summaryFrom`) und `progress`; Recht `ccap_view_reports`, Trainer nur zugewiesene Kurse/Gruppen, sonst 403 `ccap_forbidden`. Feld `completed` im Stufenaggregat (= gefestigte Fragen, GM-075). Antworten auf Lektionsquiz-Fragen laufen jetzt immer im Kontext `lesson` und speisen den Quiz-Fortschritt (GM-010). Keine neuen Hooks
- **added** · Filter `course_captain_import_package_limit( int $bytes )` (experimentell; Paketlimit für Upload und Link-Import, Standard 200 MB, nie darüber, R0-10 §3.1); Import der Entität `flashcards` und des Lektionsfelds `quiz[] {question|flashcard}` im Paketformat `cc-package` v1; Sammelfreigabe von Rechten über `admin-post.php?action=ccap_rights_release` (zweistufig, ohne JS); Audit-Aktionen `rights_override_set`, `rights_bulk_release`, `import_link_downloaded` (R1-18 g4); keine neuen REST-Routen
- **added** · Datenschutz-Selbstbedienung und Kurs-FAQ (R1-18 Nachtrag g5, R0-19 R-38/R-48): `POST /me/privacy-requests` (`type: export|erase`, 202 `{status: created|resent|confirmed}`, Bucket `privacy` 5/Tag; Löschantrag für Konten mit Verwaltungsrechten `403 ccap_forbidden`, `reason: staff_account`), `POST /me/data-exports` und `GET /me/data-exports/{uid}` (asynchroner Export; neue Katalogcodes `ccap_export_not_ready` 409, `ccap_export_expired` 410, `ccap_export_failed` 410), `GET /courses/{course}/faqs`; Shortcode `[ccap_privacy_request]`; admin-post `ccap_privacy_request` und `ccap_privacy_confirm` (GET zeigt, POST bestätigt); der vorhandene Cron-Hook `ccap_privacy_export_generate` nimmt zusätzlich `[0, user_id]` (Self-Service-Export). Keine neuen Hooks
